Case Studies
Pharma Co recognized growing risks around data reliability and regulatory compliance due to fragmented operations across its quality control labs and production units
This lack of integration led to increased chances of manual errors, inconsistent record-keeping, potential vulnerabilities during audits
Problem Statement
Solution
Pharma Co launched a joint initiative across Quality, IT, and Engineering, aimed at establishing a secure digital layer that connects every instrument to central data systems
They designed and deployed an Equipment Data Integration Framework with HiveMQ enabling consistent connectivity between instruments and core applications such as MES and LES
Implemented a cloud-ready architecture to capture, validate, and store equipment data in near real time, with appropriate data-security safeguards.
Embedded compliance-by-design features including time-stamped records, version control, and automated audit trails to meet GxP and FDA requirements
Delivered centralized dashboards and traceability reports to simplify review and ensure full visibility of equipment performance and data flow
A leading consumer goods company identified growing challenges around data reliability and process consistency due to non-standardized systems across its manufacturing plants
This lack of standardization and varied data management practices led to disconnected workflows and inconsistent reporting
Consumer Co launched an initiative to connect and harmonize all plant-level systems through a Unified Namespace (UNS)
The UNS serves as a single, structured data layer that allows seamless exchange of information between machines, control systems, and enterprise applications; eliminating the silos that had developed across plants
The company selected EMQX and Neuron as its core technology stack for enabling this connectivity
EMQX, a high-performance MQTT broker, acts as the central communication backbone, streaming real-time data securely between devices and systems
Neuron, an industrial connectivity gateway, provides protocol conversion and data normalization, ensuring that equipment from different vendors and generations can publish data into the UNS in a standardized format

The What: The event-driven concept is an emerging data transmission mechanism that has enabled new integration patterns
This system delivers events from event producer to event consumers
Events are messages sent by a component, e.g., a sensor, a machine or a system
Events are organized by event types, or topics:
Consumers receive events only to the topics they subscribed to
Different sources can publish to the same topic
Producers and consumers are loosely coupled:
Producers publish events regardless of the presence of a consumer
Producers and consumers can be removed or added without altering the system
Producers can also be consumers, and vice-versa

The What: A message broker is a software at the center of the architecture, routing events by topics to event consumers
Message brokers use topic routing logic to send events to consumers
Consumers receive only events from the topics they subscribed to
Events are stored in queuing system  which subscribers pull up from, enabling asynchronous message delivery
Upon event processing, consumer sends an acknowledgment notification to remove event from the queue
Two message brokers are often considered for OT environments:
MQTT: lightweight, standards-based, open-source, publish-subscribe messaging protocol
Apache Kafka: an open-source distributed event streaming platform
Advanced architectures combine both

I. OPERATIONS
 |  |  | 
 | Identify areas of value
Generate a list of relevant use cases to estimate financial benefits
Define benefit realisation plan
Complete full business case based on detailed plans | Monitor improvement of operations through KPIs
Update use case prioritisation based on matrix across value and technology dimensions | Track success of use cases enabled by new architecture
Monitor system health and performance in production
Provide support to users and solve operational issues
 | Map existing architecture and planned developments
Select service providers to consider
Define high-level architecture strategy
Define architecture roadmap and release strategy (incl. security)
Assess best solution for migrating architecture
Define detailed equipment-level migration plans | Establish, launch and manage architecture migration programme
Build release 1
Obtain security approvals for each release & application migration
Implement Release 1 and build subsequent releases
Link equipment to the new architecture
Link back-end system to new architecture
Decommission legacy systems | Manage software updates and patches to keep systems secure and up-to-date
Plan for future technology upgrades and expansions
 | Analyze current state operating model
Define target state operating model incl. appropriate governance, talent strategy, effective steering systems | Re-design operative processes based on new architecture
Set-up change management office & roll-out plan for large scale transformation | Provide ongoing training and development opportunities for team members.
Foster a culture of continuous improvement
